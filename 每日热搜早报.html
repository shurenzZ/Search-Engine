        数据源状态与使用说明

        使用说明（打开 / 刷新 / 要素与信号分 / 快照 / 新增平台）

        1. 如何打开

        • 双击本文件，用 Chrome / Edge / Firefox 打开即可。无需服务器、无需安装、无需登录。
        • 打开后先读一次「服务端快照 JSON」（一个静态文件，一次请求），页面立刻有内容；随后浏览器直连的实时热榜逐个覆盖。
        • 接口失败时该源显示失败原因与「重试此源」，不会用示例数据或旧数据冒充实时数据。本页面已不含任何内置示例条目。

        2. 要素、信号分与「值得关注」

        • 每条都会在本地用关键词词典抽出要素（发布上线 / 新模型 / 开源项目 / 论文研究 / 融资并购 / 政策监管 / 事故风险 …）与主体（公司 / 模型 / 产品 / 人物 / 机构），并抽取标题里的金额、涨跌幅、版本号。全部是正则匹配，不调用任何模型、不需要 Key。
        • 信号分 = 源内热度百分位 + 新鲜度 + 要素权重 + 主体命中 + 跨平台同现 + 关注词命中（0-100，鼠标悬浮可看每一项的得分）。
        • 热度跨平台不可比（微博 780 万、知乎 4 万、HN 300 分），所以热度只按同一源内的百分位计分，接口不给热度值的源（IT之家、AI 新闻、快照源）不会再被系统性埋没。
        • 分类卡片内固定分三档：🆕 发布 · 开源 · 论文（按时间倒序，不看热度）→ 📌 热度不高但值得关注 → 🔥 按当前排序。

        3. 关注词 / 只看 24h / 同事件合并

        • 工具栏「⭐ 关注」输入框填公司、模型或关键词，回车即加；命中条目加 24 分信号分并在分类内置顶，chip 上点 ✕ 移除。
        • 「🕐 只看 24h 内」按条目真实发布时间过滤；没有发布时间且不属于「当日榜」的源会被隐藏，空态会写明隐藏了多少条。
        • 「🔗 同事件合并」把同一事件在多平台的热搜合成一行，显示「N 平台在热」并累加热度；切到「按平台」视图时仍然各平台独立完整展示。

        4. 如何刷新

        • 点「↻ 一键刷新」重新抓取全部实时源，进度形如「抓取中 7/13」，每个源抓到就地更新，不必等全部完成。
        • 默认开启 13 个实时源，串行抓取约 25-30 秒；在「设置 → 启用的实时数据源」里关掉一个约省 2 秒。
        • 数据缓存到浏览器 localStorage（键名 hot_daily_brief_v1），下次打开先秒显缓存，再按「缓存时长」判断是否自动刷新。
        • GitHub 源受匿名配额限制（搜索接口 10 次/分钟、按 IP 计），页面每轮只请求一次并按 30 分钟缓存；被限流时会显示几点几分恢复，且不会反复重试。

        5. 服务端快照（浏览器拿不到的源）

        • HuggingFace 每日论文、arXiv、OpenAI / Google AI / DeepMind 官方博客、新智元、量子位、雷锋网、InfoQ、少数派、掘金、V2EX、GitHub Trending 都不开 CORS，浏览器直连必然失败，公共 CORS 代理目前已全部失效。
        • 这些源由仓库里的 .github/workflows/refresh-brief.yml 在 GitHub 服务端定时（每 30 分钟）抓取，生成 data/latest.json 提交回仓库；页面从 raw.githubusercontent.com（CORS 全开）读取。
        • 换到自己的 fork：默认按当前页面地址自动推断 raw 地址；推断不出来就在「设置 → 快照 JSON 地址」里手填。
        • 快照只做数据搬运，要素与信号分仍只在页面这一份词典里计算，不会出现两套规则打架。

        6. 如何替换 / 增加实时数据源

        • 默认使用免费开源的 60s API（https://60s.viki.moe，MIT 协议，已开启 CORS，可直接被本地页面调用）。
        • 在脚本里的 SOURCES 数组新增一项即可，例如：
          {id:'xxx', name:'平台名', short:'简称', icon:'🆕', color:'#1e88e5', path:'/v2/xxx', kind:'list', defaultOn:true, fallbackCat:'tech'}
        • path 可以是完整地址（以 http 开头则不拼基地址），里面可写 {today-minus-7} 这类相对日期；数组或 altPaths 表示多个候选地址，失败自动顺延。
        • pick：数据不在 data 根数组时写点分路径，如 pick:'items'（GitHub 搜索）、pick:'metals'。
        • titleField / summaryField：字段名不是 title / description 时指定，如 GitHub 用 titleField:'full_name'。
        • hotField / timeField：声明期望的热度与时间字段，node tools/verify-sources.mjs --client 会逐源断言这些字段还在不在——接口悄悄改字段名时只有这里能发现。
        • noProxy + cacheKey + cacheTtl：给有配额上限的接口用，本轮与 TTL 内只出网一次，且绝不把地址外发给第三方代理。
        • kind：list=返回数组；newsItems=data.news 为对象数组；news=data.news 为字符串数组。
        • dayList:true：该源给不出发布时间但本身就是「今天的榜」（掘金、Trending、历史上的今天），这样「只看 24h」不会把它误删。
        • 限流说明：60s 公共实例约「每 2 秒 1 次请求」（超限返回 429 + Retry-After）。所有出网请求走串行闸门，间隔不小于 REQ_GAP（初始 2000 毫秒，被限流自动放慢、恢复后自动提速）；整轮结束后还会对可恢复的失败源补抓一轮。
        • B站接口（/v2/bili）目前上游 500（B站反爬导致解析失败），已默认关闭；上游修复后在设置里打开即可，无需改代码。
        • 代理模式：直连失败时才用 1 个公共 CORS 代理兜底（这些公共代理 2026-10 实测大多已失效）；需要稳定跨域请在设置里填自建 Worker 作为自定义代理。接口自身返回 5xx / 401 / 403 时直接降级，换代理没有意义。

        7. 关于「原文内容」

        • 知乎、百度、IT之家、夸克、AI 新闻以及快照里的各家博客本身就带正文摘要，页面直接内联展示。
        • 点条目里的「展开全文」，会就地抓取该条原文页面并抽出正文，不用跳出去；结果按链接记忆，重复展开不再请求。
        • 微博、抖音、头条等榜单接口只提供标题与热度值，其原文页多为脚本渲染或需登录，能否抓到正文取决于源站；抓不到时点「原文 ↗」跳转始终可用。
        • 单条正文最多展示 4000 字，超出会截断并提示。

        8. 快捷键

        • R 刷新　/ 聚焦搜索　Esc 关闭弹窗或清空搜索
